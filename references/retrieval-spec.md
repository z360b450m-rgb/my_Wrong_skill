# 本地混合检索规范

## 存储与隔离

每个机构使用一个独立 SQLite 数据库。启用 WAL、外键和事务；数据库 metadata 中的 organization_id 必须与导入数据一致。题干、答案、证据、标签和稳定 `student_ref` 可索引；经授权的 `student_name` 只保存在独立结构化列并用于精确筛选，不进入 FTS 文本或向量。电话、住址、证件号等不得进入索引。

## 全文与过滤

FTS5 索引保存规范化英文/数字词元和中文字符二元、三元组，并保存不可逆的结构化作用域令牌。结构化过滤只允许预定义字段：班级、学生稳定标识、学生姓名、科目、年级、教材、试卷、题号、题型、复核状态、分数和日期。SQL 必须参数化。

搜索 `top_k` 限制为 1–100，`candidate_limit` 限制为 1–5000，查询文本不超过 4096 字符，单个过滤字段最多 100 个值。负数不得透传为 SQLite 的无限 `LIMIT`。

默认采用 bounded BM25：先由 FTS5 和作用域令牌取得最多 `max(1000, min(5000, candidate_limit*10))` 个候选，再在候选窗内按 BM25 精排。响应必须公开候选窗大小；语义和标签通道补充窗口外召回。此策略要求 SQLite 3.35+。

## 语义索引

检索固定为 SQLite FTS5 关键词召回和错误标签召回，再以加权 RRF 合并。支持增量插入、删除和 `rebuild`；`rebuild` 必须先只读核验机构归属，在同盘临时数据库完成全部写入，成功后再原子替换；不得先删除原库。不会下载模型或访问网络。

索引投影记录采用可滚动 JSON 行缓冲，默认内存阈值 256 MB，超过后转存受控本地固态目录；SQLite 写入与嵌入计算按批次读取该缓冲。结果清单必须披露阈值、是否发生落盘以及落盘目录。

## 融合

每路默认召回 200 条，使用加权 RRF（`k=60`）：

- 全文 BM25：0.45
- 向量：0.35
- 标签：0.20

结构化条件先过滤，不参与相关性打分。同分按稳定 record_id 排序。结果必须返回各分项排名、融合分、命中摘要、证据引用、索引版本和 `degraded_components`。

向量索引或嵌入提供器缺失时降级到全文+标签；使用 `--require-semantic` 时必须失败。

## 性能验收

在 8 核、32GB、NVMe、热索引和 100 万条记录下，结构化/全文 P95 不超过 500ms，top-20 混合检索 P95 不超过 1 秒，HNSW Recall@20 相对精确基线不低于 0.90。使用 `benchmark` 命令产生机器、数据量和分位数记录。
